# ADR：保留报告原始字节，分别验证本机链路和跨组交接

- 作者：马宇航，241880054，苏州校区，B13 成员一。
- 日期：2026-11-10。
- 状态：成员一实现，待成员二 Review。

## 问题

E12 需要 B 组消费 A 组独立产生的检测报告。把双方组件放在同一编排器内跑通，只能证明本地链路；重新扫描后生成新输入，也无法证明收到的报告能被消费。另外，课程生成样例不能充当实际维护项目。

## 决定

增加独立消费入口，接收报告信封、原始 payload、外部确认的两个 SHA-256、目标 commit、job_id 和 trace_id。先验证原始字节与契约，再在独立源码副本生成并验收补丁。重复 JSON 键、非有限数字、错误版本或哈希均拒绝。保留接收字节和拒绝证据，不修改旧报告 commit 来绕过版本校验。

本轮本机回放标记 `local-e12-rehearsal-not-A13-delivery`。真实 A13 报告由成员三协调，交付后再由成员一按冻结值执行。同一套逻辑可先通过本机契约测试，而不虚构对方参与。

构建源按实际运行环境选择，镜像摘要保持固定；国内服务器的镜像前缀和软件源变体与 CI 官方源分别记录。保留每次原始失败，不能以最后一次成功覆盖网络失败。

## 代价与后续

目前检测和验证仍使用编排器环境，消费结果明确记录 `draft_image_reused=false`。成员二负责真正复用 DRAFT 的不可变 image_id，并扩展真实项目目标/命令/预期输出/故障配置。成员三与 A13/教师确定真实项目来源，三人合并后再补最终实际数据验收。公共测试通过不代表这些协作项已完成。
