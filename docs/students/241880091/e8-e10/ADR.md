## 背景与约束

B轨道通过带样例提交身份的固定 MD 报告，为受限 C/Make 显式声明生成修复候选。修复前18项成员2测试出现10个行为失败，均无执行错误或跳过，集中在重复 MD、已经声明的依赖和共享变量影响范围。

约束是只修 MISSING，不删除 REDUNDANT；候选生成不写回源文件；旧版本报告必须拒绝；对无法证明范围的 Make 结构明确拒绝。本任务不要求实现完整 Make 语言，不能把文本中没看到另一次字面引用视为变量一定私有。

## 决策一：以目标与依赖二元组去重

`patch()` 使用 `(target, dependency)` 的 seen 集合，按报告原顺序保留首次编辑。相同依赖属于两个目标时是两项不同修复，同一目标需要两个依赖时也分别保留。不能只按 dependency 去重，也不对集合重排后输出不稳定计划。

替代方案是依赖路径单字段去重，实施更简单，但会遗漏另一个目标的真实缺失；按整个发现对象去重则受额外字段影响。二元组直接对应本任务的一条修复边。

## 决策二：检查当前候选已展开的声明

每次编辑重新解析 changed 文本，展开受支持的变量后检查依赖是否已经存在。已经声明的依赖直接跳过。这既处理报告内重复发现，也处理同版本人工异常重复发现，不依赖每次报告都完全无重复。

对接受后再次修复的真实场景，先提交样例的实际 Makefile 改动、重新采集报告，再调用 patch。实际结果 `NO_CHANGE`，候选字节0、计划0、未应用且源字节不变。空候选由调用流程记录为无需修改，不交给 validate 后再强行标记为 accepted。

替代方案是在 diff 末尾做字符串去重，会误伤不同规则且难以关联依赖身份；无条件追加会再次产生重复声明，均未采用。

## 决策三：保留声明风格，保守处理共享宏

direct 在目标行追加；mixed 保留原宏并在目标行追加；纯宏仅在通过私有性检查后修改变量定义。解析器跟踪变量的传递引用，包括别名和嵌套别名，并检查其他目标与配方中的使用。

发现跨目标或其他目标配方使用时返回 `UNSUPPORTED_SHARED_MACRO`；在本目标配方中的使用返回 `UNSUPPORTED_MACRO_USAGE`。即使配方文本没有被编辑，变量定义变化也可能改变命令含义，因此不能只比较 recipe 字节。未定义变量、循环引用、过深展开或无法解释的语法按受限 profile 拒绝。

考虑过的替代方案：

| 方案 | 取舍 |
|---|---|
| 直接扩大共享 DEPS | 实现短，但会影响未被报告要求修复的目标或命令，拒绝采用 |
| 克隆共享变量、重写目标引用 | 有机会缩小影响范围，但需可靠处理别名、覆盖、展开时机和作用域，超出本次受限模型 |
| 将共享宏改写成目标局部依赖 | 对部分简单样例可行，但改变原声明结构，且需要额外语义与策略验证，本轮未实现 |
| 完整解析 GNU Make | 覆盖更广，成本及风险超出本阶段；本轮明确列出不支持边界 |

本轮选择无法证明时拒绝，牺牲部分可修复率，保留可说明的影响范围与源文件不变性。

## 决策四：保留验证门及失败证据

沿用 validate 的隔离副本验证：补丁可应用、构建、功能测试、头文件变化后的增量行为和无MISSING重检全部通过，才将通过的 Makefile 写回源目录。拒绝时保持原字节；rollback字段是结果描述，不等于执行Git回滚。

E10中故意错误测试实际为test=false，其余四项true；正确候选五项全true；坏Patch在git apply --check阶段拒绝，checks为空。三种结果都符合对应预期，gate记录3行，不把成员2额外的NO_CHANGE用例混进原三行计数。

E10首次取证缺少事前备份且再次执行撞上已有目录，因此保留 `work/e10-B-manual.DE2ryT`，登记哈希后在 `work/e10-B-retry.txcvdka8` 独立重跑。事前备份必须在验证前保存，不能事后补一份冒充当时记录。最终核验同时检查新成功证据与旧失败目录完整性。

## 代价、范围与后续

实现位于 `lab.py` 的 `_repair_make_model`、`_expand_repair_variables`、`_require_private_repair_macro`、`patch`。每次编辑重新解析候选以保证声明状态一致，带来额外解析开销；本轮没有专门的性能实验，不宣称性能提升。

只支持受限的单行显式规则、普通等号变量与有界引用展开；条件声明、多目标编辑、重复定义、循环/未定义引用和其他超出profile的形式拒绝。未实现隐式规则、完整DIS/声明图或完整论文算法。scan输出的版本化报告与BuildChecker动态findings分开使用，A13服务接口兼容性另行验证。

当前HEAD比较不能单独证明工作树无未提交修改；实验流程通过固定源码、干净工作区、样例真实提交与文件字节/哈希核验补足。个人PR获审后再考虑扩展共享变量变换策略，并增加独立边界用例。
