## 5. E10：质量检查、拒绝保护与重复修复

最终选定目录：`work/e10-B-retry.txcvdka8`。

| 场景 | 实际检查 | 判定与源文件状态 |
|---|---|---|
| 故意错误测试预期 | patch_applies/build/header_change/no_missing=true，test=false，error=null | accepted=false；rollback=true；source_unchanged=true |
| 正确候选 | 五项检查全部true，error=null | accepted=true；rollback=false；source_unchanged=false |
| 无效补丁 | git apply --check 报 No valid patches in input；checks为空 | accepted=false；rollback=true；source_unchanged=true；未进入后续构建测试 |

原教学 gate 为 `track=B`、`passed=true`、`rows=3`，三行分别是预期测试拒绝、候选接受、坏补丁拒绝。拒绝案例中 accepted=false 是正确结果，完整步骤仍应退出0。

这里的 rollback=true 表示拒绝后源文件保持原字节；实现通过先验证隔离副本、全部检查通过后才写回，不能把该标志描述成已经执行了 Git 回退操作。

接受修复后，在样例内部提交真实 Makefile 变化形成 C1，重新生成同版本报告并执行动态重检。随后再次调用 `patch()`，实际结果为：

- `status=NO_CHANGE`，`passed=true`；
- `missing_count=0`，`candidate_bytes=0`，`plan_count=0`；
- `applied=false`，`source_unchanged=true`；
- 新报告 commit 与接受后 C1 一致。

这表示无需再次修改，没有调用 `validate()` 将空补丁冒充应用成功。真实 BuildChecker 重检产物与版本化 scan 报告分别保存，不直接把两种格式混作同一接口。
