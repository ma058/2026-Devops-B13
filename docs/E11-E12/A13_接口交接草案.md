## 2. 请求与产物口径

B13 已提供 [实际请求与报告原件样例](samples/README.md)：包含可用于当前服务的裸 input、增量信封、payload、完整 C0/C1、job/trace 和三个 SHA-256。来源明确为 B13 自测；A13 正式交付须使用自己的运行原件。成员一的 [个人报告](../students/241880054/e11-e12/个人报告.md) 给出环境、原件 tar 及校验值。

任务提交：`POST /v1/jobs`，JSON顶层为 `idempotency_key` 与 `input`。E12输入示意如下，真实路径及SHA由双方确认后替换：

```json
{
  "idempotency_key": "a13-b13-e12-首次联调唯一编号",
  "input": {
    "mode": "e12",
    "repo": "/course/data/已准备的项目目录",
    "base": "基线完整40位提交SHA",
    "target": "目标完整40位提交SHA",
    "candidate": "/course/data/已准备的候选Dockerfile",
    "expected_output": "1",
    "build_timeout": 600
  }
}
```

示例不是可直接运行的请求。`repo/candidate/fixed_report`必须指向**API服务器的** `/course/data/`，不是客户端电脑路径。B13在确认数据后提供可直接使用的请求文件及SHA-256；A13确认收到同一字节版本。

|接口|约定|
|---|---|
|GET `/health`|200，status与schema_version|
|POST `/v1/jobs`|有效输入202并返回job_id/status；参数错误400；同键不同请求409 IDEMPOTENCY_CONFLICT|
|GET `/v1/jobs/{job_id}`|200返回状态；不存在404；trace_id/error按任务进度返回，不假定QUEUED已有完整结果|
|GET `/v1/jobs/{job_id}/artifacts`|结果生成后200返回阶段清单；尚未生成409 RESULT_NOT_READY|
|GET `/v1/jobs/{job_id}/files/{相对路径}`|返回文件与X-Content-SHA256；不存在/越界404|

终态包括SUCCEEDED、FAILED、TIMED_OUT。报告envelope使用schema_version、job_id、trace_id、kind、commit、status、data、artifacts。`artifact://job编号/相对路径`应通过同一任务files接口读取，下载内容hash与清单/响应头对应。

full-check绑定基线commit，incremental-check/repair绑定目标commit，二者不同是正常情况。MD消费前核对目标commit、报告kind/status/schema与内容哈希；不能仅把报告commit改成目标SHA来绕过旧报告拒绝。后台管线错误保存在任务error和阶段日志中，不一定表现为POST本身400。

**独立A报告消费是新增CLI，不是给现有POST随意增加外部报告字段。** 已实现 `labs/e11e12/consume_report.py`，不重新运行A侧初始检测；接收后只在独立克隆修复并做B侧复验。当前代码明确记录 `execution_environment=orchestrator`、`draft_image_reused=false`，镜像贯通由成员2继续实现，不能宣称已在DRAFT镜像上复验。

### 独立报告交付与消费命令

A13应交 `incremental-check.json` 外层envelope、`incremental-report.json` 原始payload，以及双方提前交换确认的两个文件SHA-256、target完整SHA、job_id、trace_id、生产者代码SHA、镜像/工具链/构建参数和原始日志。两份文件按收到的原字节保存，不改写A13原任务编号、内容或换行后继续沿用旧hash。

消费命令在已具备课程编译/检测工具链的Linux实验容器内执行，路径示例须替换为实际文件；它不是Windows宿主裸Python命令：

```bash
python3 labs/e11e12/consume_report.py \
  --envelope /course/data/a13/case-01/incremental-check.json \
  --envelope-sha256 已交换的envelope小写64位SHA256 \
  --payload /course/data/a13/case-01/incremental-report.json \
  --payload-sha256 已交换的payload小写64位SHA256 \
  --repo /course/data/已确认项目 \
  --target 已确认目标完整40位小写SHA \
  --job-id 已确认A13任务编号 \
  --trace-id 已确认A13追踪编号 \
  --out /course/work/a13-consume-case-01 \
  --source-label A13-实际交付批次
```

当前校验约定须由A13互审：

- envelope为JSON对象，`schema_version=e11e12-1`、`kind=incremental-check`、`status=SUCCEEDED`；commit、job_id、trace_id与交换值一致。
- payload为JSON对象，`schema_version=e8e10-1`、commit等于target，findings为包含type/target/dependency的列表；type仅接受MISSING/REDUNDANT，目标与依赖为非空字符串。
- envelope.data与payload的JSON数据严格一致；不接受重复JSON键、NaN/Infinity或`true`与`1`等类型混淆。
- artifacts中恰有一条 `artifact://同一job_id/incremental-report.json` 引用，其小写SHA和整数bytes与下载payload一致；允许其他产物引用，但不能替代这条绑定。
- job/trace标识为安全字符的非空标识，target为40位小写十六进制SHA，两个文件hash为64位小写十六进制。repo需含该目标提交；OUT必须不存在且在源repo目录之外，重试另建OUT。

所有报告校验都先于创建输出或克隆目标。成功后保存received原件、request、candidate.patch、repair-plan、validation和真实动态recheck；当前结果沿用上游job_id/trace_id建立关联。没有可修复MD会显式返回 `NO_MISSING_DEPENDENCY`，不将空补丁写为成功修复。任何格式差异由双方明确适配/更新测试后确认，不能为了通过而篡改A13原报告。

该CLI的输出目录**不会自动注册成共享API任务**；返回的产物引用应连同B13输出归档和SHA交付，不能直接假定A13原来的files接口能下载B13新生成的补丁。上游报告下载与B13修复结果交付分别登记来源位置。

### 真实HTTP客户端

`course/e11-e12/api_probe.py` 用于共享API实际请求/轮询/下载核验。服务启动及SSH隧道确认后，A13可在其客户端取得**裸input**请求文件（不是已包装的idempotency_key/input对象）并执行：

```bash
python3 course/e11-e12/api_probe.py \
  --base-url http://127.0.0.1:18080 \
  --request 已交换的E12-input.json \
  --out 本机新的联调证据目录 \
  --key a13-b13-e12-first \
  --timeout 1500
```

脚本自行包装请求，保存health、首次/重复提交、409冲突、轮询、结果和所有下载文件，逐项核对清单/响应头SHA与bytes。它的同键冲突用例改变expected_output；新OUT不能已存在，客户端超时不表示服务端任务已终止。该脚本存在不等于服务已启动或A13已运行，实测完成后以summary、原始响应和双方记录为证。
